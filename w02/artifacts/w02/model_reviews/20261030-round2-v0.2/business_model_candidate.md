## 1. 要回答的问题与范围

本模型同时服务两个目标：理解复购变化、支持后续选择并验证改善措施；支持小林工作、减少重复整理和核对。两者分别验证，提效不直接证明复购改善。已完成初版后的三位角色二访，本轮先核查增量并修订模型，再接续知识提供和Agent同题对照；不以本周解决全部经营定义或取到后续数据为前提。

需要回答：各方所说的会员、活跃、购买和复购是什么；现有运营与门店工作怎样衔接；分析需要哪些记录与关联；哪些环节和责任尚未核实。当前不建设覆盖全公司的完整本体，不把所有岗位字段或工具都变成核心对象。

**经营起点：** 多位角色说复购连续四个季度下降，尚未取得原报表重算。沈总希望先验证“会员老化”是否主因，这只是原因假设，未取得年龄结构或因果材料，也不认定它是唯一候选原因。三个月见效是期望，提升幅度及验收口径未定，试点未获批准。阶段讨论需说明问题、范围、已有依据、待核、配合及观察方式（MSG-01619、MSG-01719、MSG-01731、MSG-01733、MSG-01739）。当前没有足够依据认定哪个改善节点价值最高。

## 2. 核心概念、必要属性及关系

标记：**角色陈述**只表示原话有来源，不等于系统和业务记录已核验；**学员选择**是当前模型取舍；**导师设计**是为分析提出的表达；**待核**不表示公司必然不存在相关定义或工作。下述建议属性不是现有字段清单，未取得实际值时不补值。

| 概念及层级 | 当前含义、依据与必要属性 | 为什么保留／重要程度 |
| --- | --- | --- |
| 会员：经营对象；类别：其属性 | 多角色说有付费会员卡、免费注册会员（MSG-01615、MSG-01679、MSG-01742）。两类在系统上不重叠为学员判断，具体资格和记录核验未完成。保留识别依据、类别、资格依据，并将资格的认定时点／适用期间列为历史比较的必要待核属性（MSG-01934、MSG-01936、MSG-01942）；不预设账号、卡、自然人一一对应 | 确定分析的是谁，避免范围混用或重复计数；高 |
| 活跃：会员分析属性 | 学员选择按业务规则、期间和范围判定活跃；各角色未提供可核定义（MSG-01719、MSG-01754）。区分规则与判断结果，材料不足记未知，不当作不活跃；“活跃会员数”是统计结果 | 避免将分析标签当身份，或跨口径比较人数；高 |
| 购买记录／订单：购买业务记录 | 老周说订单涉及线上与门店（MSG-01752）。保留记录识别、对应会员、渠道、业务时间、有效购买状态的含义；具体映射、计时点、退款取消处理均待核；二访仍未取得会员对应字段说明，购买发生时的资格能否从记录还原也未确认（MSG-01932、MSG-01938） | 支持辨认谁在何时发生符合口径的购买；订单不自动等于一次有效购买；高 |
| 复购率：群体指标 | 角色确认趋势说法但未提供公式（MSG-01619、MSG-01754、MSG-01766）。定义与某期结果分开；定义需说明人群及资格纳入时点、期间、分子分母、有效购买／复购判定及渠道；结果带所用定义、来源和覆盖范围 | 使趋势和措施结果能够比较；不编公式或直接用80万作分母；高 |
| 优惠与经营追踪：购买相关信息及可选关联 | 发放与核销不同（MSG-01648、MSG-01752）。按学员方向优先核查订单上的优惠／券、活动或其他追踪标识及其含义、来源。券方案、单张券、发放／使用记录不凭名称混同；活动归属可选 | 在有依据时联系经营安排、优惠、购买与会员；高。完整活动管理对象和专门系统暂不作为必需 |
| 反馈信息：重点业务输入 | 小林与陈姐收集、整理、对接反馈（MSG-01623、MSG-01641、MSG-01665）；学员要求高重要。保留反映什么事、来源及时间，有依据时对应经营安排或执行。实际字段、分析接收者和回流机制待核；陈姐二访已被问及后续答复和返回，但仍不能确认（MSG-01945、MSG-01953），不能写成没有回流 | 连接执行情况、调查线索、后续分析与调整；高。反馈不直接等于效果结论，不强建复杂反馈模块 |

**核心关系：** 会员与购买记录通过待核识别依据对应；订单在有证据时关联优惠、活动或其他经营追踪线索。活跃规则用于形成分析属性；复购指标按明确定义对相应人群和购买记录计算。反馈可为经营分析提供输入，但不是复购计算值或因果结论。

同一订单可能有多个追踪线索，数量与语义待核；没有标识不能直接判断未参与。关联记录也不能直接证明增量效果。只看订单会漏掉未购买的人，后续分析须按问题核查完整人群、实际动作及响应记录，但不将小林工作名单自动当指标分母。

**80万与120万：** 沈总说按80万活跃会员看变化；老周说120万是系统全量（MSG-01719、MSG-01744）。范围、时点及原始来源未对齐，不能判为同口径矛盾，不能相减算不活跃人数，也不能直接算活跃率。两类会员是否汇总及如何汇总仍待业务确认。

**资格时间维度：本轮新增的必要待核。** 我方拟先分析“门店渠道、付费会员、近四个季度”（MSG-01933、MSG-01935），具体起止日期及可覆盖期间仍未知。老周明确先补付费资格纳入统计的时点，且该业务口径不能由他代运营确定（MSG-01936、MSG-01942）。因此，资格不能仅被表达成不带时间的当前标签；本稿在会员资格和统计定义中保留认定时点／适用期间，不新增一整套卡生命周期对象或假定已有相应字段。

学员提出“购买发生时具有有效付费资格，才将该笔购买归入付费记录”（MSG-01937）。它是**待业务确认的购买归类候选规则**，不是青禾现行口径；系统能否还原历史状态也未知（MSG-01938）。这条规则没有定义复购分母、观察窗口或有效购买，不能直接成为复购率公式。付费门店的局部分析不能自动说明80万活跃人群或全公司整体趋势；免费注册会员另列其待确认口径，不拿付费规则套用。

**其他条件性保留设计：** 为活跃／复购定义保留可辨识的版本或适用期间；优惠叠加、复杂关系、活动配置等只在确有业务必要时展开。以上为建模选择，不是已发现业务变更、现有系统字段或建设承诺。

## 3. 流程视图与尚未核实的经营框架

### 3.1 角色描述的局部工作

| 位置 | 角色描述的输入、工作及输出 | 限定 |
| --- | --- | --- |
| 小林运营准备与协调 | 看未完任务和反馈，明确面向哪些会员、做什么，协调线上和门店安排；过程中记录进度问题，结束后整理反馈与待核效果信息（MSG-01623、MSG-01913、MSG-01917、MSG-01927） | 一般做法；未完任务／反馈说明关注线索从哪里出现，不等于具体名单数据来源和筛选阈值已取得。不认定她负责全部策略、制券或最终分析 |
| 陈姐门店承接 | 接活动安排后核对会员范围、参与门店、门店任务，再说明要求并安排人员；执行中收集问题和反馈，结束后整理情况，与小林对接（MSG-01665、MSG-01667、MSG-01949） | 小林补充门店情况通常找陈姐（MSG-01915），与陈姐的描述相互支持到一般协作层面，尚未对照同一实例。两类会员分别核范围，人员／执行仍需确认；实际任务完成标准仍待核 |
| 反馈整理与交接 | 小林、陈姐均描述反馈收集或整理，但具体由谁分析、怎样使用结论尚不清楚（MSG-01641、MSG-01665、MSG-01945、MSG-01953） | 陈姐二访已问回流仍未知；小林二访未取得实际接收者或分析返回。反馈参与准备是线索，不证明某次活动已有完整的效果分析闭环，也不证明公司不存在闭环 |

**岗位产出与核心对象分开：** 小林原话是“整理名单”及希望助手“把需要关注的会员整理出来，把建议依据讲清楚”（MSG-01637）。“目标会员名单”是导师归纳名称，当前只作运营流程的可能输入／产出及提效需求，不建立独立核心对象；生成、交接、反复整理原因和Excel实际工作流留后访。建议关注人群、实际选定人群、统计人群不可混同。门店任务保留在流程视图，不默认存在全公司通用任务模块。

**工作支持的两段候选用途：** 小林希望获得“需要关注的会员＋每条建议依据”，减少原有整理核对（MSG-01925）；陈姐希望提前看清会员适用范围、参与门店、门店任务、答复责任与待核事项（MSG-01947、MSG-01953）。两者分别放在运营准备和门店承接处；目前尚无证据证明小林的一份实际输出已经完整提供了这些信息，不把两项愿望直接连成已运行系统。

小林确认自己可说明活动安排、执行进度和反馈；系统数据找老周、门店情况找陈姐，统一统计口径不是她一个人决定（MSG-01923、MSG-01929）。这些是各方可参与的范围，不等于材料已交付、分析负责人或最后定义确认人已落实。小林亦不能确认注册考核规则（MSG-01907）；王经理先前将其作为核查线索（MSG-01824），这次转交没有解决责任归属，不应据此给小林增加制定权。

### 3.2 我方为分析和共创保留的框架

复购变化观察 → 口径及证据核查 → 分群与原因分析 → 措施选择／策划 → 运营与必要的门店执行 → 反馈及结果整理 → 效果分析 → 下一轮经营判断。

这条完整链是我方调查框架，不是青禾已验证标准流程。复购监测、统一口径核查、原因分析、上游策划、效果分析和下一轮决策是否实际开展、谁承担、怎样衔接均待核，可能隐性存在、由一人兼任或尚未开展；不能虚构专岗或公司规模。

沈总描述业务优先级、召集与推动待决事项；老周描述核查用途、范围和技术条件的协作建议，均不代表全部分析责任已明确（MSG-01721、MSG-01725、MSG-01752、MSG-01760）。可以先分析口径和证据明确的部分，不必等待全链查清；完整框架本身不证明复购下降原因或改善效果。

## 4. 规则与边界

1. 统计必须说明会员范围、期间、购买计入条件、渠道与来源；有规则或材料缺口时保留未知。现有标签的真实填写含义待核，不凭标签名当分类依据（MSG-01742）。
2. 发放、核销、购买、复购改善分别取证；“发给谁”不等于“谁能使用”。优惠来源和系统／人工／混合限制待核；权益说明、回访等不使用券的动作不套发券流程。
3. 小林说人群和方案仍需业务人员确认，未授权自动发券、联系会员或改记录（MSG-01637、MSG-01919、MSG-01925）；“业务人员”具体是谁仍待核。对整理结果表示有帮助不等于已能执行，也不扩大授权。
4. 门店适用范围、工作量、记录和现场问题应在安排中澄清。**信息整理完成与执行安排确认必须区分：** 陈姐对整理办法的回应保留人员、工作量、现场答复、具体执行和工作记录仍需门店人员及相关同事确认（MSG-01947、MSG-01953）。这是一项关键行动条件，不新建通用审批／异常模块。两类会员要分别核对当次活动范围，不能预设要求一定不同（MSG-01949、MSG-01951）。陈姐的考核顾虑保留；店长协调、上下宣导和反馈协调仍是学员设计方向，不当作现行制度或个人活动否决权（MSG-01665、MSG-01681）。
5. 老周目前提供配合核查说明，未交付具体数据、未批准数据权限、未落实核对时间（MSG-01760、MSG-01938、MSG-01942）。个人Excel不等于公司统一口径、统计或考核依据（MSG-01907、MSG-01923）。小林说会绕开系统用表，但操作与原因仍需看实际工作（MSG-01909、MSG-01911、MSG-01917），不能写成已证实的系统功能缺陷，也不据此把模糊表记录纳入核心对象。
6. 小林提效和复购改善分别观察，后续区分建议采纳、实际执行及结果变化。任务耗时、效率基线、复购原因与因果效果尚未验证。

## 5. 候选动作与下一轮待核

近期候选是由运营和技术在明确用途与范围后，核查可用记录，必要时人工整理或导出支持分析；当前不宣称已可导出或已关联成功。系统帮助小林整理关注会员和说明依据仍是候选支持方向，不预先指定完整名单工作流。独立活动系统、复杂配置与反馈处理模块留作后续有价值依据时再讨论。

### 5.1 支持工作与未来观察：候选，不是已见效

| 候选支持 | 本次取得的使用条件及依据 | 拟怎样检查与未完成项 |
| --- | --- | --- |
| 小林关注会员及依据整理 | 需帮助减少原有整理／核对；仅多一套工具而原有工作不减，期待低（MSG-01925）。名单仍作流程产出，不新增核心名单对象 | 取得实际任务和前后材料后，看输出是否可用、是否替代部分既有操作、还需哪些人工确认。具体效率基线、筛选规则、实例均未取得；不是量化验收条件 |
| 门店执行前信息整理 | 对我方提出的办法，陈姐认可两类分别核范围、列清任务／答复责任／待办的方向，预期减少前期确认（MSG-01946、MSG-01947、MSG-01953） | 陈姐提出前／中／后三处观察：开始是否讲清、执行中是否少来回确认、结束后原来反复询问是否减少（MSG-01951）。尚无实际试用、基线或结果，不声称已有提效或获批试点 |

“多了三步”在小林二访中被澄清为主观操作负担感受，不是精确步骤清单（MSG-01919、MSG-01921）；不据此写具体页面、不将它定为旧项目失败根因或预计可减少三步。

上述两项可以用于准备小范围验证，但重要程度不等于开发优先级或已证明价值最高。复购改善依赖另行核实统计定义、实际执行与业务结果，不能用信息更清楚或省事替代。

### 5.2 取证状态与后续入口

没有新材料时不自动安排一轮相同问题。以下保留有用的缺口及证据入口，不要求在本周清空。

| 后续问题 | 先向谁核查及所需依据 | 当前处理 |
| --- | --- | --- |
| 会员资格时点、活跃／复购定义、80万／120万范围与来源 | 业务核定义，老周核实际记录能否支持；具体确认人、原统计说明、样例和时间仍待补 | 时点已被二访定位为关键缺口；购买时有效资格只是候选归类，不是复购公式 |
| 会员—订单—优惠／经营追踪关联、有效购买 | 老周与运营对照样例、字段含义、渠道、缺失及多个标识、退款取消等 | 会员关联、历史状态已问仍未知；优惠关联、退款等二访未实质推进，不记为已核 |
| 优惠策略、制券／配置、发放与适用对象控制 | 小林说明自身参与并指认实际经手人；业务核规则，老周核配置与使用记录 | 保留系统／人工／混合控制可能 |
| 权益说明、未购回访等非券运营 | 小林还原一次实际工作中的对象、动作、时间、执行／响应记录及交付 | 保留没有后续订单的人，不强套优惠券 |
