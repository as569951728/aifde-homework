# 模型范围澄清：来源、归属和入模用途

状态：导师根据第三组学员标注与提问作出的整理。当前先澄清层级，不继续追加审核项；不能把学员困惑视为整批认可。两条原始标注及完整提问保存在 human_feedback.json。正式作业文件未写入。

## 先纠正此前的混排

上一轮“目标会员名单、门店任务、反馈”是业务信息／对象候选，不是三个属性值。“来源、时间、状态”等才是建议属性；具体某条记录填写了什么，才是属性值。举例：会员是对象；会员类别是属性；付费会员卡／免费注册会员是角色提到的类别取值。我们尚未取得某个具体会员的真实记录，不编造实例值。

此前表格将核心概念、岗位流程产出和导师字段建议并排，容易使人以为它们都是公司已定义的本体对象或系统字段。这是导师的组织问题，本轮按用途重新分层。

## 四个问题分别判断

| 维度 | 判断什么 | 青禾例子 |
| --- | --- | --- |
| 来源 | 谁说了什么；哪些名称、字段或关系由导师设计 | 小林说整理名单；“目标会员名单”作为对象名称及形成时间／版本等是导师抽象，不是她逐项提出 |
| 业务含义 | 通用概念在青禾具体指什么、规则是否已明确 | 会员、订单是常见概念；青禾会员资格、有效购买及复购算法仍须确认。常见名称不等于通用规则可直接套用 |
| 所属对象与使用范围 | 信息描述什么，在哪个业务判断或流程中被使用 | 会员类别描述会员，不因小林提到就挂到“小林岗位”下面；门店任务进度描述任务，适用需要门店承接的流程 |
| 维护和确认责任 | 谁录入、谁使用、谁有权确认定义；是否受访问权限限制 | 小林维护个人Excel，不证明里面的信息是她的私有业务概念，也不证明它是公司统一口径。实际责任及权限另据材料核实 |

公司专有／通用、公司共享／岗位局部、来源是谁、由谁维护，是不同维度，不能互相替代。岗位使用的属性可以是公司共享概念；只由一个岗位使用的规则也可能决定关键业务状态，并不因此不能入模。

## 本周模型的范围

任务书第3步要求为本次业务问题说明必要对象、定义、属性、关系、规则、来源和取舍；是单客户初稿，不要求建立覆盖公司所有部门的完整本体。我们当前围绕复购改善及支持小林的效率目标，分三层表达，不把三层全部升级为核心对象：

| 内容 | 来源与当前核实程度 | 本轮放置及用途 |
| --- | --- | --- |
| 会员、类别 | 多角色陈述两类；具体资格待核。两类不重叠是学员已采用的判断 | 核心业务概念，界定分析对象与人群范围 |
| 活跃属性、复购指标 | 角色未提供可核统一定义；属性定位、定义与结果区分是已获学员认可的建模选择 | 核心分析语义，保留规则及期间等依赖，具体值待核；不重审已认可的划分 |
| 订单及经营追踪关联 | 老周说明线上／门店渠道；属性和轻量追踪为导师结合学员意见提出 | 核心业务关系与待核映射，支持购买分析；不宣称系统已打通 |
| 需要关注的会员集合／工作名单 | 小林 MSG-01637 说整理名单，希望助手整理需要关注会员。“目标会员名单”是导师命名；生成、审批、交接、版本皆未核 | 当前放在小林流程的输入／产出和提效需求，不单列核心本体对象；详细属性移到后访，不继续要求逐字段审批 |
| 门店执行任务 | 陈姐描述安排和反馈，完成标准未知（MSG-01665、MSG-01667）；字段表由导师拟议 | 放在线下承接流程，保留做什么、由谁承担、交出什么、怎样算完成的必要信息。不据此默认独立全公司任务对象或系统 |
| 反馈信息 | 小林和陈姐均有收集、整理、对接的陈述（MSG-01623、MSG-01641、MSG-01665）；学员将其重要程度提高 | 作为本轮重点业务信息及反馈回流关系保留，重要程度高；对象化程度只取所需，不等于开发复杂反馈系统 |
| Excel列、个人排序、模板样式等工作载体细节 | 个人记录存在，但行粒度和具体内容尚未取得 | 当前仅作调查依据与岗位支持的后续设计，不能因提到文件就入核心本体 |

是否进入核心模型，重点看：它是否影响本轮定义、计算、关键动作、交接或结果判断；业务含义是否足以描述；当前粒度是否必要。多岗位共享是有用线索，但不是入模硬门槛；常见字段也不会因为通用就自动全部加入。

## 两条标注的处理

**目标会员名单：** 小林确实提出“把需要关注的会员整理出来，把建议依据讲清楚”（MSG-01637），但未提出一个叫“目标会员名单”的公司对象或确认其字段。也不能把助手建议关注的会员、某次活动实际选定的人群、指标统计人群视为同一集合。当前取消独立核心对象定位，将来源、筛选、交接、反复整理原因留后访；未来若实际存在多方交接、稳定身份或必须管理的版本／状态，再按证据评估是否单独建模。支持小林提效的目标继续保留。

**反馈：** 按学员意见将本轮业务重要程度提高到高，优先梳理其收集、整理、交给谁分析、如何进入下一轮调整。当前最低必要表达是反馈反映什么事、来自谁及何时、有依据时关联哪项经营安排／执行。属性表达是导师建议，不是已验证字段；不能把反馈直接当量化效果或下滑原因。分析责任、归纳与客户原话的区分、回流是否实际发生仍待核。重要程度高不代表所有反馈功能必须优先开发。

完整分析仍要明确人群范围，必要时包含未购买者；这不要求把小林的工作名单当独立公司对象，更不能直接拿它作复购率分母。
