## 观察与取舍

| 检查点 | 原版/v2实际表现 | v3实际表现与判断 |
| --- | --- | --- |
| 模糊工作载体是否成为核心对象 | 原版将个人工作记录列入当前模型；v2明确列为核心“工作记录”对象，仍未解决范围问题 | v3明确“不把Excel工作记录建成核心对象”，放在数据使用边界，记录粒度及实际工作流留待调查；本项改善 |
| 一般核对是否泛化建模 | v2将“核对输入类型”列为必要区分，仍容易把概述提升为核心模型关系 | v3将该候选作背景/待定，明确不足以建立独立对象或关系；本项改善 |
| 是否重复送审已有反馈 | 原版把0020/0021再次放进核查组；v2文字说不重复，但组名仍含方案边界 | v3明确0020/0021已有反馈、本轮不重复送审；本项改善 |
| 后访未知是否阻塞初稿 | v2下一步要求带实际Excel核查，容易把取实物变成初稿前置 | v3说明可先保留未知边界，把查看记录放进另列后访任务；本项改善 |
| 必要异常是否被过度删除 | 原版和v2均保留身份不一致时停止检测、审核后才能出报告 | v3继续保留两项关键规则，个人进度表不进核心模型；说明本样例没有因筛选规则而丢失必要异常 |
| 目标、限制及未知是否保留 | 前后均保留未测时间、未同意自动动作、任务/项目关系不明等边界 | v3仍保留这些边界，没有以效率改善推断复购效果；未见这一范围的退化 |

人工发现的局限，不能被“调用成功”掩盖：
1. Qinghe回放只选了局部候选，不能用于证明整个经营闭环已建好。v3的整体结构仍局限于这段材料，不是完整青禾模型。
2. 回放输入省略了原始导出的meeting role_id。原版和v3对speaker=assistant提出额外角色核对，属于夹具元数据不完整造成的干扰，不能当作真实访谈角色存在冲突，也不作为前后优劣证据。完整课程提取仍沿既有role_id处理规则。
3. 假设案例v3先把状态列在样品名下，又注明状态归属待核，表达仍有不一致；正式建模应把状态归属标为未知，不能直接采用该属性挂载。方法改善没有消除人工核查。
4. 单次回放不证明稳定收益或适用于所有行业；没有测量学员审核耗时，不能承诺效率提升比例。三组Skill比较涉及模型随机性，本记录只报告可见行为。

导师判断：采用v3作为后续整理的当前方法，保留上述局限；不采用回放内容为客户事实或正式业务模型。客户字段、分析阈值、角色分工仍来自实际材料及人工反馈。
