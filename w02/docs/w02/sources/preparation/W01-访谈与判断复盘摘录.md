#### 新增重点：问法会影响回答

老师本页的两种问法分别把“直接打标签、发券”和“第一阶段只给名单建议”放在问题里，角色都回答可以。这是课堂教学示例，**不是我们正式访谈中沈总说过的话**，不能补入正式客户证据。

两种同意不能证明完整的执行范围已定，也不能仅凭字面不同就认定客户反复或存在已确认冲突。先比较问题中的时点、范围、前提和场景；如果含义仍不一致，再保留分歧并请求澄清。

优先问实际发生过的工作，再讨论可能的方案。例如以下是后续练习问法，不是已发生的访谈：

- 对小林先问：“最近一次会员召回，名单确定后，下一步实际做了什么？”根据回答再逐步核对谁审核、谁执行、怎样反馈和卡在哪里。
- 涉及助手执行时，再向老周核实哪些动作可以开放、通过什么批准和技术控制实现，不把小林的使用偏好当作系统权限。
- 对沈总问阶段成果与取舍；若提供方案供选择，明确其为候选方案，允许对方提出其他方案或说明尚不能决定。

**不把“你同意我的方案”误读成“我已经发现了你的需求”。** 人工审核是否必要、建议是否采纳、动作是否执行、业务是否改善，都要分别确认。

#### fit-gap 与立项判断的经验

1. **每行写客户想得到什么。** 产品功能放进能力和证据；“核清口径、核对报表”是调查任务，应放进报告待核项及相关诉求的下一步。旧 GAP-003 的问题有必要，但放置位置需要修正，保留原记录与迁移说明。
2. **分类与证据状态分开。** 分类是当前判断的满足路径，证据状态是依据的充分程度，完成/验收另看。已有标准能力与明确的客户适配边界，可先判系统适配；“尚未适配完成”不能一概写成待判断。
3. **已核实必须说清对象。** 样例名单正确不证明青禾名单可用；单一角色多次表达仍是同源陈述。客户材料明确未接入数据，可以支持“尚未接入”的事实，不能扩大为权限、数据质量或适配效果已经确认。
4. **未知与暂不承诺分开。** 不知满足方式时保留待判断；当前明确不作业务效果或交付保证时写暂不承诺。三个月是客户期望，不能因技术验证通过或方案获批就承诺止跌回升。
5. **四问都落到行动。** 业务问题、产品适用与边界、推进条件、阶段决定，每问写缺什么、找谁、怎样验证。带条件继续要写明先继续调研/方案设计，取得必要条件后再评审是否开展验证。
6. **先验证具体的一部分。** 拟在获准的脱敏样本上，按确认规则识别净消费下降会员并生成有依据建议，分别核对计算、名单及建议可用性。采纳率是信号之一，同时看准确性、修改成本与不采纳原因；不能用净消费下降代替复购率。

#### 记录和提交时的提醒

- 每条访谈证据至少保留：角色/日期或消息编号、问题原文、回答原文、内容类型、证据状态、支持到哪一步、仍缺什么及找谁核实。截图中的教学案例单独标记，不混入客户原始转录。
- 保留失败和限制，不为过检查修改结果。实际提交包也要解压核对报告、引用证据及路径；本机检查通过不证明压缩包完整，技术检查通过不证明客户适配或业务效果。
- 当前经验已记录，正式作业修订尚未完成。原始访谈和已提交基线保留；以后修订说明原判断、新判断、依据及迁移去向，不把后来复盘写成当时已知。

**后续访谈前的一步：先选一个待支持的决定，确认该角色能回答什么，再准备一个核心问题。** 不把本节变成另一份要整段发给客户的提纲。
