# 变更单 CR-01：B7-C01「本月」未澄清（2026-11-09）

提出方：交付方。提出依据：王经理 04838 核查意见。状态：**已按书面流程提出**；04840 核查意见认可"变更单里的待核内容可按书面流程走"；是否纳入本期由客户方按流程定，本单不代填批准。

## 1. 变更来源

| 项 | 内容 |
| --- | --- |
| 触发 | 第二轮 SOW 讨论（04837）中就"本月"类问法征询处理方式 |
| 客户意见（04838 原文要点） | 不宜按本期已知限制接受；月度统计只支持完整自然月且需具体月份，含糊问法应先问清是哪个月；当前直接返回不支持会形成验收依据上的缺口，**明示也不能替代修正**；若要求本期修正，按范围变更走书面流程提出 |
| 我的理解 | 客户要求的是**行为修正**（缺月份时先追问），不是加一句说明 |

## 2. 变更内容

把"未绑定具体自然月的相对时间问法"（本月、上个月、最近这阵子等）对 `full_month_only` 指标的处理，从 `unsupported` 改为 `clarify`：先追问目标月份并给出可选月份选项，用户确认前不查询。

## 3. 影响与范围判断

| 维度 | 评估 |
| --- | --- |
| 改动位置 | 意图解析层的日期默认规则（`product/w03_intent_prompt.txt`）。现有规则把"相对时间按参考日期解释"，且"时间范围已明确但指标不支持 → unsupported"；"本月"被解释为参考日所在月（2026-09），因非完整自然月被拒 |
| 能不能在我们自己的模块里改 | **不能**。构建 Skill 只产出指标定义，判定程序只比较结果，二者都不决定"缺月份时该追问还是该拒绝" |
| 是否超出本期已确认范围 | **是**。本期范围写的是"只开发构建 Skill 与判定模块"，标准内核由现有工程框架提供。改意图层等于改内核行为 |
| 波及面 | 所有相对时间问法（本月、上月、近三个月等）的解析行为，不只 B7 一项；改后需重跑小样本全部用例与规模集，并复核日期边界相关用例是否被带偏 |
| 费用与排期 | 金额待谈，本单不填估算值；排期取决于客户是否批准纳入本期 |
| 若不批准 | 本期按缺口交付：B7-C01 保持失败记录，SOW 明示该行为与"含糊问题应先澄清"不一致，列入验收缺口清单，不计为已通过 |
