# 青禾业务建模：监督方式与边界

2026-11-07导师补充备稿。本人随后纠正“监督”为“进度”；本稿源于导师对笔误的理解，保留作过程参考，不登记为本人另行要求、采纳或本轮主要成果。实际进度见《W03-学习会话接续.md》最新停点。

这里监督的是业务知识是否有依据、模型表达是否正确、使用模型时是否出错，以及各项状态是否如实登记。

## 谁负责什么

| 参与者 | 主要职责 | 不能替代的事项 |
| --- | --- | --- |
| 本人（学员/FDE） | 确定任务目标与边界，参与证据无法解决的真实业务取舍，反馈是否采纳导师稿 | 本人的学习判断不自动成为客户正式制度、生产授权或验收 |
| 主导师Agent | 整理原材料、修改候选、安排测试、修复已有依据可解决的问题、维护版本与接续记录 | 自己编写的稿子不能自称已获独立审核；导师修订不能登记为本人独立作答 |
| 独立业务模型/测试Agent | 先对照原材料形成判据，再审模型、预期及实际回答；指出语义、来源、粒度和范围问题 | Agent结论不等于客户确认，也不能把没有运行的用例写成通过 |
| 确定性检查工具 | 核文件指纹和输入隔离；日期检查器独立复算字段、条件、区间及结论 | 不能独自确认自然语言引用是否支持断言、真实业务是否生效；这些仍需来源复核 |
| 客户角色及真实确认责任方 | 在其掌握与职责范围内提供业务事实、规则依据、实际记录及正式确认 | 一位角色的口述或总结认可，不自动构成公司批准或最终验收 |

## 当前的五道检查

1. **来源检查。** 保留原问答及提问前提，区分本人W02/W03访谈、指定青禾材料、课堂案例、导师推导和人工测试情境。作废W04访谈不入模型输入；小林产品范围、陈姐日期端点、04邮件统计选择、05字典字段分别归属。
2. **正文检查。** 检查对象、关系、带范围的规则、实际工作及未决事项。按本人决定，个人Excel和FDE费用/延期/交付过程放在过程记录与SOW，不混入业务知识正文；不把规则已有口述与正式凭据缺失混为一谈。
3. **先定标准再运行。** 问题、情境、预期、候选版本在运行前冻结；被测模型每次只看规定材料与本题，不能看到预期、其他题答案或独立计算结果。独立Agent先形成来源判据，再对照作者预期，降低同一推理链自证风险。
4. **分层判读。** 运行成功、格式可读、日期计算正确、解释自洽、来源支持、完整回答通过分别记录。日期检查器用正例、故意破坏例和文字语义边界例检验；实际回答再由独立Agent阅读全文。最终结论正确不能抵消错误解释或出处。
5. **版本与写入检查。** 原始失败、旧候选和已提交基线保留；每轮限定范围与调用次数。正式写入前必须核对要写入的具体版本及必要验证。当前来源细化候选是独立副本，原生工作流待写入的proposal3仍是旧第三稿，两者不能混用。

## 监督尚不能证明什么

独立Agent有单独审查上下文，但仍是AI，可能与作者共享盲点；来源复核、确定性计算、错误对照和本人必要判断需共同发挥作用。多次测试或引用同一份来源，不等于获得独立的客户事实证据。

目前仍在候选验证阶段。旧版本成绩不自动属于新候选，有限测试通过不证明所有情境或生产适配。规则口述已取得的部分可用于合成测试推导；正式规则文件、历史执行凭据、生产记录与最终验收权限仍按实际缺口保留。尚未完成38项指标查询及数值验证，也未据此获得客户验收。

实际进度以[学习转实操接续](../../../W03-学习会话接续.md)和[测试入口](test_design.md)最前面的当前停点为准；本说明不改变正式模型或审批状态。
