## U02 · 概念含义与状态区分

在当前模型中，会员账户、会员卡、等级、付费资格、活跃、购买记录和复购率分别表示什么？请说明它们的区别，并举一个同一账户同时具有不同属性或状态的例子，指出哪些状态不能相互推出。

```json
null
```

### 实际回答

按当前业务模型（W03第三稿候选，尚未写入）的表述，这些概念不在同一层，不能互相替代：

1. 会员账户：经营与统计对象，一行一份CRM会员账户；账户不等于跨系统自然人，也不等于自然人数。属性包括注册日期、归属门店、会员等级。依据：《数据字典》members；MSG-01615、01679、01742。
2. 会员卡：卡归账户，一个账户可对应多张卡；属性包括卡产品类型、权益开始日期、计划权益结束日期、提前终止日期（可为空）、购卡实付金额。购卡实付不是商品订单收入，也不直接裁定资格。依据：《数据字典》cards；MSG-03848、03854、03886。
3. 会员等级：普通、银卡、金卡，与付费资格是两回事；资料只给当前等级，当前等级不能还原过去各日的等级。依据：《数据字典》members.tier；MSG-03848、03866、03870。
4. 派生付费资格：不是永久身份、会员等级、活跃状态或购买事实。就本期总部运营月报而言，其含义是：给定业务范围与判定日，账户存在一张同时满足产品范围与有效期的卡；必须由同一张卡同时满足产品范围和有效期，不能把不同卡的条件拼接判断；多张有效卡不重复计账户。依据：小林MSG-03848、03854；陈姐MSG-03886、03888。产品范围只约束本期总部运营月报，正式规则文件尚未取得。
5. 活跃：按业务规则、期间与范围判断的会员分析属性，当前定义未知；不是第三类会员身份，未知不判为不活跃。依据：MSG-01719、01754。
6. 购买记录／订单：一行一笔订单，保留订单识别、关联账户、渠道、下单日期、支付状态、原价、实付、累计退款、原始购买件数等含义。支付状态不等于有效购买；有效购买是已支付且实付减累计退款后大于零，取消与全额退款不计为有效购买。本期材料未提供订单实际使用哪张卡的关联。依据：《数据字典》orders；MSG-01752、01938；《订单日报说明》《财务邮件》《数据字典》。
7. 复购率：群体指标，不是单个账户的固有属性。定义需明确人群、资格纳入时点、期间、分子分母、有效购买条件与渠道；结果还需定义版本、来源与覆盖。依据：MSG-01619、01754、01766；《会员运营周报》。

区别可概括为：账户、卡、订单是对象或记录；等级、活跃是分析属性；付费资格是按范围与判定日派生的账户级判断；有效购买是订单级条件；复购率是群体指标。账户数不能当自然人数；卡数不能复制订单；订单也不能反推具体卡；归属门店与订单成交门店是不同关系，不可互相替代。

构造示例（依据模型构造，不是客户真实记录）：账户A等级为普通，持有一张悦享年卡且在判定日有效，另持有一张体验卡（不纳入本期月报范围）；账户有一笔已支付订单，但累计退款等于实付。按本期总部月报口径，A因同一张悦享年卡同时满足产品范围与有效期而具有付费资格；但等级仍是普通，不能推出金卡；体验卡不影响该资格；那笔支付订单不是有效购买；也不能据此推出A活跃或会复购。若A还有第二张有效悦享年卡，账户仍只计一次，订单也不因卡数复制。

不能相互推出的状态包括：账户存在或注册不等于付费资格；付费资格不等于等级、活跃、有效购买、复购或永久身份；卡数量不等于订单数量；订单不能反推具体卡；等级不等于付费资格，当前等级不能还原历史等级；购卡实付不代替卡类型与有效状态；支付状态不等于有效购买；单笔有效购买不等于复购，更不等于复购率；活跃定义未知，不能因未购买或无有效卡就判为不活跃；复购率群体结果不能还原为某个账户状态。

依据与缺口：上述对象定义主要来自模型第2节及其标注的《数据字典》和角色消息；付费资格与产品范围来自小林MSG-03848、03854，日期端点来自陈姐MSG-03886、03888、03890，且端点说明限于本期已说明的悦享年卡与家庭季卡；活跃定义、复购率原报表重算、正式规则文件、生产身份与历史资格核验、订单与具体卡关联仍缺依据，相关判断应保留待核范围。

## U03 · 关系、统计粒度与关联路径

请用“一个对象可以对应几个对象”的方式说明账户、卡、订单和门店之间的关系。假设账户归属A店、订单在B店成交，按成交门店查购买应归哪边？能否从现有关系确定订单使用了该账户的哪张卡？请说明依据及未知。

```json
null
```

### 实际回答

按“一个对象可以对应几个对象”说明：
- 账户—卡：一个账户可以对应0至多张卡；一张卡归一个账户。依据：模型第2节关系与边界及《数据字典》cards（账户—卡一对多，卡归账户；多张有效卡不重复计账户）。
- 账户—订单：一个账户可以对应0至多笔订单；一笔订单关联一个账户。依据：模型第2节关系与边界及《数据字典》orders（账户—订单一对多）。
- 账户—归属门店：一个账户有一个归属门店（members.home_store_id 为账户归属字段）；按字段关系，门店端可关联多个归属账户，但模型未单独展开门店对象和门店侧统计规则。
- 订单—成交门店：一笔订单有一个成交门店（orders.store_id 为交易发生门店）；按字段关系，门店端可关联多笔成交订单，同样未单独展开门店侧规则。
- 卡—订单：没有已给定的直接对应关系；二者都关联账户，但一个账户有多卡、多单并不表示能确定某单用了哪张卡。

题设“账户归属A店、订单在B店成交”，若按成交门店查购买，应归B店，而不是A店。依据：模型第2节明确会员归属门店描述账户归属，订单成交门店描述交易发生门店，两者是不同关系、不可互相替代；按成交门店口径使用订单的 orders.store_id。A店仅是该账户的归属门店。

能否确定订单使用了该账户的哪张卡：不能。现有关系只有账户—卡一对多、账户—订单一对多以及二者均关联账户；本期材料不提供订单实际使用哪张卡的关联，不能据卡数复制订单，也不能据订单反推卡。该结论是对现有关系范围的判断，不是生产数据核验结果。

依据与未知：上述关系主要见模型第2节“核心对象、属性与关系”“关系与边界”及《数据字典》members、cards、orders 字段说明；归属/成交门店区分见同节“归属门店与成交门店”。未知包括订单与具体卡的实际关联、生产环境自然人身份与历史资格对应、门店侧统计口径及确认人、优惠/活动追踪与订单反馈的实际关联等，仍待实际记录和相应负责人核实（模型第5节）。
