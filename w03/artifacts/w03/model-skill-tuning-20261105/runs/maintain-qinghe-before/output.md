# 业务模型局部更新草稿（W02，隔离回放，待人工确认）

## 问题与范围
- 目标：支持小林减少会员名单整理与重复核对负担，形成可审核的重点会员识别结果和建议依据；人群与执行方案仍由业务人员确认。
- 本轮不判断复购效果，也不将助手视为自动发券、联系会员或修改记录的授权。
- 已采纳内容继续有效：小林希望识别重点会员并得到可审核建议；其具体采用条件待核。

## 整体结构
- 参与者：小林（使用与审核）、业务人员（确认人群和执行方案）、老周/数据提供方（数据来源、字段、覆盖与许可待核）。
- 输入：会员基础、消费等数据；青禾口径、比较时段、字段与覆盖范围未知。
- 动作/状态：按已确认口径识别需关注会员 → 形成名单与建议依据 → 人工审核/确认 → 后续执行不由助手自动完成。
- 输出：可供小林整理和核对的重点会员名单、每条建议的依据说明；具体格式和可用标准待核。
- 交接：助手减少重复整理，但不能替代业务确认；实际渠道、权限和审核分工未确认。

## 核心模型内容（局部）
- 会员：青禾语境下的会员；定义、比较时段和重点经营规则待核。
- 重点会员候选：按业务规则筛选出的名单；筛选规则、名单使用标准、样本范围待核，不能把标准样例上的筛选结果等同于青禾已适配名单。
- 建议与依据：每条建议需说明依据；事实准确性、采纳标准和审核分工待核。真实运行能生成建议，不证明业务可用，也不证明复购改善。
- 权限边界：助手不得自动发券、联系会员或修改记录；“人群和执行方案由业务人员确认”已有本轮原话支持，但具体审核分工、渠道和权益仍需确认。
- 减少整理负担（待FDE反馈的设计约束草稿）：小林希望先整理需要关注的会员、说明依据，减少重复整理名单和反复核对不一致信息；如何衡量“减少”待核。

## 背景与调查待办（不进入核心流程）
- 小林提到“上一个项目最后没人用”，界面让她感觉操作“又多了三步”；她明确这不是精确操作清单，具体页面和步骤需结合实际界面核实。该信息只作为采用风险和设计约束线索，不能用来补写现状流程，也不能断言本系统会增加三步。
- 若新系统只是增加一套工具而原有工作量不减少，小林期待会低；具体验收和衡量方式待定。

## Fit-gap复核（草稿）
- GAP-001仍为系统适配/待核。“识别重点会员并输出可用名单”不变；会员定义、规则、时段、数据字段与许可、名单可用标准仍需小林和老周确认。标准筛选样例只证明标准能力，不证明青禾筛选口径已适配。
- GAP-002仍为待判断。“可审核、可实际使用”不变；新增材料支持把“减少重复整理/核对、不单纯增加工具负担”作为待确认的可用性观察点，但是否写入采纳标准需FDE判断。审核分工、渠道、权益、采纳率口径仍未核实。
- GAP-003保持历史转入待核清单，不当作新增交付诉求，本轮不据此扩展范围。

## 关键未知与依据边界
- 青禾会员定义、重点经营规则、比较时段、数据来源/字段/覆盖/许可、名单格式与可用标准。
- 小林的审核流程、采纳标准、渠道与权益、人工核对耗时和错误情况。
- “上一个项目”的具体界面和步骤不掌握，不能编造。
- 现有标准语义与样例运行只说明能力边界；人工发现过月份错误和资格待核，不能将自动通过等同业务可用。
