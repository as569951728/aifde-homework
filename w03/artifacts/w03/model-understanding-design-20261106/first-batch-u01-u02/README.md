## U01：这份模型为什么存在

**给被测者的问题：** 请用业务语言说明青禾这份业务模型服务哪些目标。复购原因调查、口径核查、本期查数和小林的岗位支持之间是什么关系？哪些成果能够支持下一步判断，哪些还不能说明业务效果？

**导师示范（面向更新后的目标认识，不是当前v0.4的实际回答）：**

青禾需要理解复购为什么变化，进而选择并验证改善措施；同时希望减少小林重复整理和核对。沈总提出的会员老化仍是假设，原因调查不能被“先做一套工具”替代。对齐会员范围、统计口径和记录，是开展原因分析的前提。

本期在合成测试数据内形成有定义、可追溯、可独立核对的问数，能帮助小林检查人数口径及重复、遗漏，并为后续分析建立一致基础。它不能证明真实复购下降原因、岗位已经省时、三个月见效或投资回报；后续还要取得对应真实记录、明确经营措施及观察条件。

| 判据 | 必须说清什么 | 需要拦住的回答 |
| --- | --- | --- |
| 目标 | 复购原因／改善与岗位提效分别观察 | “系统上线就是项目成功” |
| 关系 | 原因调查是目标，口径与记录核查是前提，本期查数支持核对和下一步判断 | “只要把口径统一就完成了原因分析” |
| 证据边界 | 阶段技术结果与真实原因、采用执行、业务效果分开 | “38项算对，说明复购已经改善” |

依据：W02沈总01731／01733／01737／01739、小林01925；W03小林03856／03860／03866／03870及04／07材料。具体来源路径与消息定位见[审核者预期](reviewer_expectations.json)及[补充来源清单](freeze_manifest.json)。示范里的阶段组织属于有来源的导师归纳，不是客户已经批准全部交付。

## U02：模型里的概念分别是什么

**给被测者的问题：** 在当前模型中，会员账户、会员卡、等级、付费资格、活跃、购买记录和复购率分别表示什么？请说明它们的区别，并举一个同一账户同时具有不同属性或状态的例子，指出哪些状态不能相互推出。

**导师解释表（审核参考，不作为答案送给被测者）：**

| 概念 | 当前建模含义 | 不应混淆成 |
| --- | --- | --- |
| 会员账户 | 本期关联记录与统计所用的CRM账户，一账户可对应多卡、多订单 | 已统一的跨系统自然人 |
| 会员卡 | 关联账户的权益记录，有产品和有效期间 | 会员等级、订单或独立计数的一名会员 |
| 等级 | 普通／银卡／金卡这类账户属性 | 是否具有本期付费资格 |
| 付费资格 | 在业务范围和指定日期下，根据纳入卡及有效状态作出的判断 | 永久身份、已购买或已获营销联系授权 |
| 活跃 | 依业务定义、期间、范围判断的分析属性；具体定义仍待核 | 与付费／免费并列的永久第三身份，或随意规定的购买阈值 |
| 购买记录／订单 | 购买行为的记录，需区分有效购买及时间范围 | 卡记录或会员本身的固定属性 |
| 复购率 | 对某群体、期间和规则计算的指标；定义与结果分开 | 单个会员的身份，或有任何一次购买就有复购 |

上述是当前采用的业务表达，不要求采用唯一的数据库或本体设计；不同表示方式只要保留相同的概念区别、条件和范围，可以接受。

**导师构造的例子：** 某账户等级为普通，月末有一张本期范围内且有效的家庭季卡，本月没有有效购买。它有本期付费资格，但不计入本月付费购买人数；是否活跃仍需活跃定义，不能直接判“不活跃”。不能把复购率当作这个账户的固定身份，也不能因为有资格就自动纳入可触达名单。

其中月末购买人数的结论用于说明“资格与购买不同”，依据小林03868及04邮件；不要求业务模型正文硬编码所有报表分子分母。这个例子不是实际CSV账户或已运行结果。

**判定方法：** 七个概念的含义与相互关系要自洽；允许用自己的话或其他有依据的例子。若把等级当资格、把活跃当第三身份、将资格等同购买，或把群体比率当个人身份，记需修订；只给一串名词不算完成解释。预期内容足够但缺输入依据时，应记录覆盖不足，不用常识补齐后冒称模型已有。
