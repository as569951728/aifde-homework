# 从目标与证据找缺口

方法版本：v0.1，2026-11-04。本 Skill 用于 Codex 读取本地资料的准备环节，不依赖已有新访谈，也不启动课程提取工作流。W03 的具体入口见 [适配说明](references/w03-adapter.md)。

先确认本次要支持的决定、目标范围、现有工作版本和输出位置。沿用用户约定，一次处理一个指标或一个有关联的小范围；若用户要求全量盘点，再覆盖全部目标。保留旧模型、原答复及已提交版本。

将目标、旧模型、最新适用材料、字段说明及必要的小样本放在一起核对。先列已明确的依据，再找缺口：旧模型写“未知”不代表本期材料仍未说明；字段存在、样本碰巧符合、其他场景的参考答案也不能补成业务定义。比较同一对象、时间和用途，版本新不自动意味着覆盖旧规则。

按性质区分：

- **业务规则**：对象、资格、状态、范围或有效期含义，确认后进入业务模型。
- **统计选择**：本报表的时间归属、分子分母、观察时点、支持维度，进入指标定义并保留适用范围。
- **字段或覆盖**：主键、关系、记录粒度、数据可还原性、时区/单位或授权范围，向有依据的材料和实际责任方核查；不能由字段名字猜业务规则。

只登记尚无足够依据、且会改变本轮结果或行动的缺口。每条给出关联目标、现有依据、具体缺什么、误判影响、核查对象及要看的记录或一个核心问题。注明阻塞的部分；不影响的工作继续。“材料已明确”与“实际数据已验证”分别记录。若没有缺口，写明核过什么、下一步验证什么，不为显得完整而安排访谈。

涉及角色说法，检查完整问题与回答：提问者先放入的前提、角色附和、个人感受和直接诉求不混同；未核实不写成组织不存在。缺谁的依据就找谁，不把转交线索当成制定权或授权。已有明确回答不重复追问。

沿用现有缺口/取舍表。保留 ID 及含义，关闭或迁移时写依据、状态和去向；复核后不变也留下核过的当前证据。分类、证据强度和完成状态分别写。客户诉求与调查动作分别放置，历史追踪条目不算新增承诺。

输出供审核的简短结果：已知依据、真正缺口、处理去向、唯一下一步。给学员的理由与可发给客户的问题分开；不冒称已经访谈、应用模型或得到学员/客户确认。后续取得新来源再交业务模型维护方法，不能把准备稿塞进访谈来源。

# W03 使用范围

工作根目录为 `W03/实操工程`（相对 AIFDE 仓库根目录）。只读 `customer/w03/targets.json` 中本次选定的目标、`docs/w03/business_model.md`、`docs/w03/interview_notes.md`、`materials/w03` 对应客户材料与字典，必要时检查 `data` 下小样本；先核实际路径，不整体发送规模 CSV。

当前 W02 v0.4 是接续起点；其未知与本期已给资料逐项比较。课程参考问答不作为本人访谈来源。原始四表是数据接入层，不能把字段当成已经完成的业务语义。

结果沿 `docs/w03/interview_notes.md` 的“缺口清单”保存。试用、方法评测输出放在 `artifacts/w03` 的独立方法验证目录，不能记成本人已完成作业。业务规则与报表统计选择的去向分别是业务模型和指标定义；不在找缺口时直接生成 38 项指标。

任务书第 4 步规定本周王经理必访，即使某项指标已无规则缺口也不能取消；可核阶段交付、验收依据与责任，不必重复问材料已明确的公式。本期是否已访以本人记录为准。

取得本人新访谈后，才把实际导出配置到 `customer/w02/extraction.json`，再按 `customer/w02/workflow.json` 使用维护 Skill。sources 为空的当前工作流不得启动；找缺口不需要解除这个保护。不得 resume W02 未采用草稿或直接 apply 旧提案。
