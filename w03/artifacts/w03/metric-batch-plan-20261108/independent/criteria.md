# 独立设计审核判据（先于候选审查）

形成时间：2026-11-08。范围：38项状态登记、批次与测试设计；不执行构建、问数或全量期望核算。依据当前 materials/w03/01—06、docs/w03/test-guide.md、contract.md、旧版 full-test-design-20261106/v2 两份指标计划，以及 net-sales-first-20261108/completion.json 和 independent/final-review.json。

1. **完整且诚实登记**：任务清单38个ID各出现一次，中文名相符；来源核定、测试设计、独立期望冻结、真实构建、真实查询、解释审核和规模回归分别记录。当前仅 net_sales_cents 在small和8题范围内闭环；其余37项尚未真实构建/查询。原38项设计不能冒称38项可运行测试或结果。net_sales新增计划也不能继承8题的已通过状态。
2. **业务批次与构建依赖分开**：批次可按金额、订单状态、去重/件数、均值比率、注册/首后续、普通月内、付费月报组织，粒度清楚、无遗漏重复。比率分子分母及派生模型须依赖闭合；跨批依赖可回引已审范围，但不能据此宣称只生成比率自身就能加载。累计重建或隔离局部构建的选择应在批前固定，均另建目录/项目并保留失败；同名模型、SQL和粒度不一致不能merge，更不能手工追加measures或改生成SQL后冒称Skill已修复。重建后须回归原已通过题及本批新增题。
3. **逐项可复核设计**：每项至少有完整自然语言问题、明确要抓的错误、期望业务状态/语义、独立核算方法、所需数据证据、来源及执行门槛。数值未算时只用计划字段，不伪装正式expected.rows；缺少数据区分力须标待补fixture，不用猜数补齐。
4. **关键边界**：含取消的创建数、全退仍计支付、严格正净有效、全退要求实付正值、优惠不扣退、原始件数非净销量；去重在查询范围重算；先在全覆盖历史确定首单再筛窗口、同日按订单号；比率先汇总分子分母再相除，零分母null；所有时间起含止不含，覆盖外unsupported而非0。
5. **共享测试不虚增覆盖**：通用状态、12维度、judge注入、同义问法、规模计划须明确对应批次/指标和执行状态。共享资格规则覆盖六项须各留账户/订单/分子分母归属，不能一项正确推出六项正确；模型理解问答不能替代指标查询。共享用例不重复计数，同义题不计新增业务边界。
6. **月度限制与资格证据**：普通月内三项与付费六项分别处理；材料03只写整月/全店，contract的full_month_only当前又限制全渠道，二者应注明业务依据与引擎支持边界，不能偷称原材料已确认全渠道或安排当前无法执行的渠道查询为ok。付费六项按月末、同一张卡同时满足范围和有效性、账户去重、资格先选再取当月订单；有效起点含、计划结束与提前终止不含、跨月逐月重判。正式执行前仍核对原访谈连续上下文，不把旧计划本身当客户原文。
7. **执行门槛与结果判定**：运行前冻结定义/原始数据/期望；期望独立于被测Skill、SQL和actual。small/scale分别形成期望。纯judge比较完整status、intent、列、组身份和值、units、版本，区分0/null/缺行；解释另审。数值同值不能证明排除取消或原订单归退款日，需结构证据/有区分力的样本。受控error故障与正常业务测试分开。
8. **可批量推进而不越界**：批内可自动修复有来源可解决的问题并复审，无需逐指标等待；真实事实冲突、需要客户取舍或超出授权才汇总交本人。通过门槛后接下一批，不以设计审核替代数值/解释审核。W02基线、业务模型正文和现有正式tests不被本轮登记覆盖。

最终审核输出review.json与review.md，固定被审文件及哈希；status、approved、failed_checks和正文结论必须一致。设计通过只表示本轮登记/计划可用，不是执行授权升级、指标已验证或客户验收。
