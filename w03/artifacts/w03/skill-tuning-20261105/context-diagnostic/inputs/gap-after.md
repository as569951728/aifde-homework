# 对齐目标后找缺口

方法版本：v0.3，2026-11-05。本地准备工具；不依赖新访谈，不启动正式提取。W03 入口和脚本使用见 [适配说明](references/w03-adapter.md)。

## 建立可核查的输入

先读目标目录，保留本次选定 ID、准确名称、其他目标名称及原始材料。用 `scripts/prepare_scope.py` 将目录名称与材料二级标题精确对应；若已提供 `scope_packet`，核对其目录和来源，不重复准备。脚本只做定位，未匹配或同名多 ID 时回看任务原文，不从 ID 猜业务含义。全文保留，不因标题不同就删去跨章节依赖、字段或共同边界。

目录已经将两个项目分别命名时，先按选定名称的原文定义分析，不再泛问“当前是这一个还是另一个”。只有实质定义冲突、无法定位或缺依赖时才提缺口。另一个项目的限制不自动成为本项目的限制；当前项目确有引用或依赖时，则必须纳入，不因“其他目标”标签一律排除。

## 只登记会改变当前判断的未知

将当前定义、旧模型、字段说明及必要小样本对照。区分：业务规则进业务模型，本报表的时间/分子分母/范围进指标定义，字段粒度/覆盖/可还原性进数据核查。旧模型的未知被当前适用资料说明时更新状态；字段名、样本巧合或参考答案不能补成业务规则。

先写已有依据与来源，再列真正缺口。每个缺口写关联目标、缺什么、现有依据、影响、核查对象及一项具体取证动作；标出阻塞哪部分，不阻塞其余工作。若材料已足够，明确“没有新的业务定义缺口”，下一步核实际数据，不凑访谈问题。固定测试快照和未来生产出报制度分开；材料已明与数据已验证分开，覆盖外不是零，单位和时间边界保留。

涉及角色说法，核问题前提、回答范围和后续限定；附和不作独立证实，直接体验/诉求仍保留。未取得规则不推成组织无规则；角色转交不等于制定权或授权。需要访谈时只提出当前关键问题，解释与可发送文本分开。

沿用原缺口/取舍表，保留 ID 和含义；关闭或迁移写依据、状态、去向；不变也记录本期复核证据。客户诉求与调查动作分别放置，分类、证据强度和完成状态分别写。不假定草稿已采纳、客户已确认或实际访谈已发生。

## 输出前逐项核对

结果只含当前目标的已知依据、缺口及去向、唯一下一步。逐项核对：这条问题是否由当前目标必需？原文是否已有答案？是否误把相邻指标条件移了进来，或漏掉本目标真实依赖？对照具体来源修正后交审核。

按用户约定一次一个指标或有关联的小范围；只有明确要求全量才扩展。原提交与原答复保留。准备稿不加入访谈来源，取得实际新来源后再交业务模型维护方法。

# W03 使用范围

工作根目录为 `W03/实操工程`（相对 AIFDE 仓库根目录）。读取 `customer/w03/targets.json` 的目标目录并选定本次目标、`docs/w03/business_model.md`、`docs/w03/interview_notes.md`、`materials/w03` 对应客户材料与字典，必要时检查 `data` 下小样本；先核实际路径，不整体发送规模 CSV。

当前 W02 v0.4 是接续起点；其未知与本期已给资料逐项比较。课程参考问答不作为本人访谈来源。原始四表是数据接入层，不能把字段当成已经完成的业务语义。

结果沿 `docs/w03/interview_notes.md` 的“缺口清单”保存。试用、方法评测输出放在 `artifacts/w03` 的独立方法验证目录，不能记成本人已完成作业。业务规则与报表统计选择的去向分别是业务模型和指标定义；不在找缺口时直接生成 38 项指标。

任务书第 4 步规定本周王经理必访，即使某项指标已无规则缺口也不能取消；可核阶段交付、验收依据与责任，不必重复问材料已明确的公式。本期是否已访以本人记录为准。

取得本人新访谈后，才把实际导出配置到 `customer/w02/extraction.json`，再按 `customer/w02/workflow.json` 使用维护 Skill。sources 为空的当前工作流不得启动；找缺口不需要解除这个保护。不得 resume W02 未采用草稿或直接 apply 旧提案。

准备索引：在工程目录用 `.venv/bin/python ../学习工具/fde-gap-review/scripts/prepare_scope.py --catalog customer/w03/targets.json --target 所选ID --material 对应材料.md 字典.md --output artifacts/w03/本轮目录/scope.json`。材料仍需保留全文；没有标题精确匹配时回看任务与原文，不据标题索引自行补定义。只接受来源明确的目录名称，不把索引当业务核定。
