# 2026-11-05 作业工具继续优化

**找缺口 v0.3 进入带人工审核的试用；业务模型维护继续用 v3，v4.2 未晋升。** 本轮16次真实调用，结构均成功，语义不是全部通过。改善依赖完整输入与方法配合，不能归功于多写几句提示。W02原提交、W03当前v0.4业务模型及正式访谈记录均未改。

## 具体改了什么

1. 新增[目标材料定位脚本](../../../../学习工具/fde-gap-review/scripts/prepare_scope.py)：读取目标目录的准确名称，定位对应原文章节，同时展示其他目标。只做精确标题索引，不猜定义、不裁定冲突、不裁剪全文。任务范围和查询契约作为必需上下文一并提供；缺上下文或输出已存在时拒绝写入。
2. [找缺口 Skill v0.3](../../../../学习工具/fde-gap-review/SKILL.md)：先确定当前目标及真实依赖，再分业务规则、统计选择与实际数据验证；已有规则不重问，真实缺口不隐藏。使用方式见[W03适配说明](../../../../学习工具/fde-gap-review/references/w03-adapter.md)。未全局安装、未接正式自动apply。
3. 新增[问答上下文整理脚本](../../../customer/w02/evaluations/prepare_evidence_context.py)：逐条核候选引文，带回所引回答之前的问题和相邻消息，保留原ID。不会替人工判断是否存在引导或是否支持主张；引用缺失/不匹配会报错。课程原 `show_evidence` 只返回候选直接引用的消息，不能假定它已经展开前置问题。
4. [维护 v4.2 候选](candidate-maintain/SKILL.md) 改为 `business_model` 与 `notes_update` 独立产出，并缩短重复指令。隔离回放仍未解决前提来源遗漏与正文混入取舍说明，因此**没有替换现用 v3**。已启用的提取提示v2保持原样。

## 验证怎么做

沿用11/4原语义标准：G4项、M6项、H6项、J4项；新增保内资格正向对照P4项，共24个判定点。未改期望迎合输出。原提取E三项未受改动，不重复调用。

- 首轮10次：旧缺口方法原输入、补目录索引、同索引换新方法；维修新旧对照；真实资格缺口正例；青禾/维修维护新旧对照。维护两组都用分字段输出，不能将其效果独归新版文字。
- 首轮没有晋升。查出输入接口问题后，候选方法保持不变，另存[输入诊断](context-diagnostic/诊断说明.md)，补真实任务清单、查询契约、维度目录及原问答邻接索引；旧新各对照，另跑修正的正例，共5次。
- 缺口方法通过适用检查后，单独重复青禾原请求1次；[请求核验](request-verification.json)确认两个请求完全一致。维护仍失败，原两模块确认门禁保留false，没有继续重跑维护挑选结果。

这一输入诊断是在发现缺失上下文后对原计划的有据扩展，未覆盖首轮失败、未再修改候选Skill。总计16次调用，不是16次都通过语义验收。

## 实际结果

| 检验 | 本轮观察 | 决定 |
| --- | --- | --- |
| 只加目录索引 | 能区分净销售额与月末付费会员净销售额，但仍把交付范围、未来生产出报制度当成待问项 | 仅目录不足，必须带任务与运行边界 |
| 完整输入的青禾缺口 | 旧v0.2为3/4，新v0.3为4/4；相同新请求再跑一次仍4/4 | v0.3限完整输入、人工审核试用 |
| 维修普通关闭数 | 新旧均4/4；不引入保内条件，已有规则不重问 | 原正确表现保留，不虚报新增收益 |
| 真实保内资格缺口 | 显式给出依赖的正例v2为4/4；保留卡种/失效端点待核，并采用有明确依据的共同关闭规则 | 不是“一律不问”或“一律排除相邻材料” |
| 青禾维护 | v4.2原输入4/6；补原文上下文后仍4/6；未完整交代01918前提，正文仍出现取舍指令 | 不晋升；保持v3 |
| 维修维护 | 旧v3为5/6，新v4.2为6/6 | 留出改善不能抵消青禾失败 |

旧缺口方法的G2/G4在人工复核时上调：确认任务要求的验收依据和责任，可以是合理下一步，不应只因与新版动作不同就扣分。对旧方法使用同样标准，保留了这项合理表现。详见[首轮判读](semantic-initial.json)、[输入诊断判读](context-diagnostic/semantic-review.json)、[相同请求复验](gap-confirmation/semantic-review.json)。

本轮还发现一个测试设计问题：合成正例v1未明确子指标继承普通关闭规则，P3却预期继承。因此保留该项为“不可判定”，没有把模型拒绝继承判为错误，也没有回改原输出。另存有R4显式继承依据的正例v2再验，不能宣称原例已通过。这也是验证过程需要核对期望依据的原因。

找缺口最终三个适用案例12/12，青禾重复额外4/4；只是这些材料上的通过数量，不是成功概率、课程成绩、节时比例或普遍稳定性。判读由同一导师完成，并非独立盲评。没有跑正式W03工具工作流、访谈、指标构建或客户验收。

## 下一步怎样用

本周一次只处理一个目标，使用顺序为：**任务范围/查询契约＋目标目录＋本期材料/旧模型 → 定位索引 → 缺口草稿 → 本人和导师核原文**。遇到材料明确、实际数据未核的情况，进入数据核对，不能自动变成客户口径缺失。

实际小样本路径是工程 `materials/data/small`，已从build配置和文件确认。回放“未提供CSV”仅指隔离输入没有数据，不表示本机缺文件；下次先读取现有orders小样本，不重复索要已在本地的数据。王经理必访仍保留，用于阶段交付、验收与责任。

维护工具的下一次优化，应在审核前独立完成证据取舍，再从获准的较窄表达组织正文，并验证两个产物；当前v4.2及上下文索引都不能代替这一语义审核。本轮停止继续调用维护，不改工程工具或申请新的客户确认来掩盖方法问题。
