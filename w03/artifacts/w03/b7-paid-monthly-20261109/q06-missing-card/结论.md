# B7-Q06 卡表缺行受控实验

日期：2026-11-09。目的：验证未决事项 O7——"卡表缺行时，系统能否区分'数据缺失'与'确实无卡'"。

## 设计

以 `qinghe-w03-20260923-small` 为源，复制一份派生数据集，只删一个会员的全部卡记录，其余文件不动：

| 项 | 内容 |
| --- | --- |
| 被删记录 | C0000014／M00013／家庭季卡／valid_from 2026-08-31／valid_until 2027-01-01／未提前终止 |
| 该会员订单 | 2026-08 两笔有效订单，净额合计 4650 分 |
| 卡片总数 | 22 → 21 |
| 数据集 id | `qinghe-w03-20260923-small-v2` |
| 位置 | `data/`，清单 `manifest.json` 已按新数据重算 sha256 与 counts |

M00013 的原卡恰好是 `valid_from` = 月末判定日的端点用例，删掉它同时验证端点会员退出后的表现。

## 独立期望

按月末资格规则直接读 CSV 重算 2026-08：

| 指标 | 含 M00013 | 缺卡后 |
| --- | --- | --- |
| 购买人数 | 6 | 5 |
| 有效订单数 | 10 | 8 |
| 净销售额（分） | 47550 | 42900 |
| 复购人数 | 4 | 3 |
| 复购率 | 66.67% | 60% |
| 订单均额（分） | 4755 | 5362.5 |

## 结果

运行 `run-v2`（干净口径）：

- 返回 `status=ok`，数值 `5 / 8 / 42900 / 3 / 0.6 / 5362.5`，与独立期望完全一致。
- **回答中没有任何关于卡数据可能缺失的提示**，措辞为"付费资格按月末当日符合悦享年卡或家庭季卡有效条件的账户判断"，把缺行直接当作"该会员无合格卡"。

## 一次污染与排除

首次运行 `run/` 的回答末尾出现"存在受控的会员卡记录缺行场景"一句。追查确认：这句话来自我写在 `manifest.json` 的 `derivation_note` 字段，被系统当作数据集描述读进回答，**不是**系统自身识别出缺行。

处理：删除 `derivation_note` 与 `derived_from`，数据集 id 改为中性名称，重算清单，用 `run-v2` 重跑。中性清单下该提示消失，说明系统只能读到别人告诉它的信息。

两次运行都保留：`run/` 有污染、`run-v2/` 为有效结论。

## 结论

**O7 成立。** 现有实现无法区分"卡记录缺失"与"会员确实没有合格卡"：缺行会让该账户静默退出统计，数值随之变小，回答与告警都不体现异常。在真实交付中，这意味着卡表不完整时，六项付费月报会给出偏低但不报错的数字。

据此，O7 从"待确认的限制"升级为"已验证的限制"：只能依赖客户保证卡表完整，或后续增加卡表完整性校验（比对会员表与卡表的应有关联、检查卡有效期断档）。本稿仍不自行填补该缺口。
