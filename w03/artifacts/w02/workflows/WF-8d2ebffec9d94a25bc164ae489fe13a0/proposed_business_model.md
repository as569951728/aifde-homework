# 青禾会员经营业务模型（W03 草稿，待人工确认，未写入）

## 1. 业务目的与适用边界

模型服务两个分别观察的目标：理解复购变化并支持选择、验证改善措施；减少运营在日常名单与执行信息上的重复整理和核对。岗位提效不能直接证明复购改善。

沈总希望第一阶段先验证复购下降原因，并先检验“会员老化”是否主因（其个人判断）；多位角色称复购连续四个季度下降，但尚未取得原报表重算。三个月见效是客户期望，提升幅度、验收口径、试点范围和批准均未落实（MSG-01719、01731、01733、01737、01739）。沈总定业务优先级、召集与推动待决；具体专业口径和操作由相应业务／数据角色核实（MSG-01725）。

沈总所说80万指其所说的活跃会员，老周所说120万指系统全量会员；两者定义、范围、时点、来源均需分别核查，现有依据不支持相减、算活跃率或断言同口径矛盾（MSG-01719、01744）。

适用边界：本期业务知识依据课程合成测试数据（覆盖2024-09-01含至2026-09-01不含，Asia/Shanghai，日期粒度）与青禾角色访谈。测试库中的账户、卡、订单关系可用于本期分析，但不等于生产环境自然人身份已统一、历史资格可还原或权限已获批准（MSG-03873、03875、01760、01942）。

文中「角色陈述」表示有原话依据；「建模选择」表示分析侧的取舍；「待核」表示信息不足，不表示公司不存在相关工作。建议属性不等于现有系统字段。

## 2. 核心对象、属性与关系

| 对象 | 当前认识与最小属性 | 依据与保留理由 |
| --- | --- | --- |
| 会员账户 | 经营与统计对象。账户不等于跨系统自然人，也不等于自然人数；是否与其他系统身份对应待核。属性含注册日期、归属门店、会员等级 | 多角色陈述 MSG-01615、01679、01742；字典与老周 MSG-03873、03875。高重要：确定统计与去重单位 |
| 会员卡 | 卡归账户，一个账户可有多张卡；属性含卡产品类型、权益开始日期、计划权益结束日期、提前终止日期（可为空）、购卡实付金额。购卡实付不是商品订单收入，也不直接裁定资格 | 小林 MSG-03848、03854；陈姐 MSG-03886；陈姐与小林均说明多卡并存。高重要：资格判断的唯一载体 |
| 派生付费资格 | 不是永久身份、会员等级、活跃状态或购买事实。含义为：给定业务范围与判定日，账户存在一张同时满足产品范围与有效期的卡。判定日由具体业务或统计要求确定 | 小林 MSG-03848、03854；陈姐 MSG-03886、03888。高重要：月报人群与名单口径的共同基础 |
| 会员等级 | 普通／银卡／金卡，与付费资格是两回事；本期资料只提供当前等级，无变更历史，因此不能据现状推断企业过去从未有过其他等级 | 小林 MSG-03848、03866、03870。高重要：防止以等级代替资格 |
| 归属门店与成交门店 | 会员归属门店描述账户归属，订单成交门店描述交易发生门店，两者不是同一关系，不可互相替代 | 字典、老周 MSG-01932；净销售额分组核查记录。高重要：门店维度口径 |
| 购买记录／订单 | 一行一笔订单。保留订单识别、关联账户、渠道、下单日期、支付状态、原价、实付、累计退款、原始购买件数的含义。订单与卡之间本期材料未提供“实际使用哪张卡”的关联，不推断 | 老周 MSG-01752、01932、01938；字典。高重要：支撑谁在何时发生有效购买 |
| 有效购买 | 本期资料含义：已支付且实付减累计退款后大于零；取消与全额退款不计入。支付状态不等于有效购买。累计退款是截至快照的累计额，不是带退款时间的事件；原始商品件数不等于扣退货后的净数量 | 本期材料《订单日报说明》《财务邮件》《数据字典》（原文见核查记录）。高重要：所有购买类统计的共用语义 |
| 复购率 | 群体指标，定义与某期结果分开表达。定义需人群、资格纳入时点、期间、分子分母、有效购买条件及渠道；结果需定义版本、来源与覆盖 | MSG-01619、01754、01766；本期材料。高重要：保证可比，不用80万直接当分母 |
| 活跃 | 按业务规则、期间与范围判断的会员分析属性，定义仍未知；不等于第三类会员身份，未知不得判为不活跃 | 学员建模选择；各角色未给明确口径（MSG-01719、01754）。高重要：避免把未知当结论 |
| 优惠与券 | 优惠是购买相关信息，券是可能载体。发放、核销、购买、复购改善分别是不同事实 | 陈姐、老周 MSG-01648、01752；小林 MSG-03860、03862。高重要：连接经营措施与购买 |
| 反馈 | 现场问题与执行反馈是经营输入，保留事项、来源、时间；有依据时关联经营安排或执行 | 陈姐、小林 MSG-01665、01945、01953。高重要：连接执行与后续调查 |

关系与边界：
- 账户—卡为一对多，账户—订单为一对多。本期材料未提供订单与具体卡的对应，不得据卡数复制订单或据订单反推卡。
- 不建立“免费注册会员”与“付费卡持有人”互斥分类；两类说法只见于角色陈述与学员判断，账户可能同时具备多种形态（MSG-01615、01679、01742）。
- 名单、执行记录等是工作载体：本期只保留其用途与实际工作情境，不把某一载体升为业务对象。
- 活动、优惠追踪与反馈之间的关联是后续核查方向，实际字段、一对多关系与重复计数风险均待样例确认；无购买的参与者也应能被观察。

## 3. 可复用的业务规则

1. **纳入产品范围（本期总部运营月报）**：只纳入悦享年卡与家庭季卡持有人。异业联名卡即使收费，也由合作方经营，不属本期自营会员范围；体验卡不纳入。该口径只约束本期月报，不改其他报表（小林 MSG-03848、MS丛-03854）。属性范围以角色陈述为依据，正式规则文件待核。
2. **资格判定方式**：账户只要有一张符合本期范围且在判定日有效的卡即具有付费资格；同一账户其他失效卡或不纳入范围的卡不影响该判断。必须由同一张卡同时满足产品范围与有效期，不能把不同卡的条件拼接（小林 MSG-03848、03854、03870；陈姐 MSG-03886、03888）。等级与购卡实付金额不得代替卡类型与有效状态判断资格（小林 MSG-03848、03866）。
3. **权益有效期端点**：权益在生效日期当天起有效；有效期结束日期当天已无效；存在提前终止日期时，从提前终止当天起无效。提前终止为空仅表示该记录没有提前终止，仍受计划结束日期限制，不等于无限期，也不证明当前或某历史日必有效（陈姐 MSG-03886、03890，属门店经手人说明）。资格按要求的判定日期检查，不能只看当前状态；本期月报取月末（陈姐 MSG-03886、03888；本期统计确认材料）。
4. **去重**：多张有效卡不重复计账户，也不重复累计订单（小林 MSG-03848；陈姐 MSG-03886、03888、03890）。
5. **有效购买与退款归属**：采用第2节“有效购买”语义；退款按原订单日期归属，取消与全额退款不计（本期材料）。
6. **统计口径要求**：任何人数或金额统计需明确会员范围、期间、渠道、有效购买条件与来源；标签字段含义应结合实际填写核实（MSG-01742、01754；本期材料）。
7. **优惠与措施取证**：券发放、核销、购买、复购改善分别取证；发放对象不自动等于允许使用对象；权益说明、未购回访等非券措施按各自动作与响应记录核查（MSG-01623、01648、01752、01917）。
8. **人群与执行确认**：人群和执行方案由业务人员确认；候选条件不是小林一个人能定，需相应负责人确认；助手不得自动发券、联系会员或改记录（小林 MSG-03856、03860、03862）。
9. **门店承接条件**：门店配合前需先明确活动适用范围、具体工作量、现场问题由谁处理、门店工作如何记录；要求不清或影响门店考核的先澄清再安排（陈姐 MSG-03886、03888）。
10. **数据协作边界**：老周可检查数据用途、安全、范围与技术条件，条件不清可要求暂缓接入；访谈未批准具体权限、交付数据或承诺日期（MSG-01760、01768、01942）。

## 4. 实际工作与决策条件

| 环节 | 输入／触发 | 参与者动作 | 输出与交接 | 条件与未知 |
| --- | --- | --- | --- | --- |
| 日常会员运营 | 经手会员优惠券活动、会员权益说明、对一段时间未购买会员的回访（小林 MSG-03860） | 先明确面向哪些会员、准备做什么，再确认执行方式和协作人；跟进发放与使用反馈；整理结果与尚未核实的问题（MSG-03862） | 整理后的名单与执行信息；找相关同事确认线上或门店的执行安排，再按记录跟进进度（MSG-03858） | 具体活动、候选名单、筛选条件小林不能确认，须查实际记录并由相应负责人确认（MSG-03862）；线上实际经手岗位及具体业务确认人未明确 |
| 门店承接与执行 | 运营侧的执行安排与范围信息 | 陈姐核对会员范围、参与门店、具体任务，向门店说明并确认人员与执行安排（MSG-01665、01949、03888） | 执行中收问题与反馈，结束后整理情况，与小林对接 | 门店依据同一套有效期规则逐卡核对再按账户归并（MSG-03888），但完整门店任务尚未安排；完成标准待核 |
| 反馈整理与后续 | 执行中的现场问题与结果 | 陈姐向小林对接现场反馈；小林收集整理反馈（MSG-01641、01665、01945、01953） | 反馈汇入下一轮安排 | 后续由谁分析、答复如何返店未知；局部交接有双方陈述，完整闭环未验证 |
| 数据核查协作 | 具体对象、范围与用途说明 | 小林说明运营用途；老周核对取数条件、统计范围、时间与统计说明，并列出待补记录与待确认责任；陈姐补门店情况（MSG-01923、01929、01938、01942、03877、03881） | 核查过程记录与待确认清单 | 老周明确不预先承诺交付，测试库结论不作生产规则或验收结论；统一口径确认人、分析牵头人与权限待定 |
| 业务决策与责任 | 阶段范围、口径与考核问题 | 沈总定业务优先级与推动；专业口径由运营／业务规则负责人确认，IT 配合字段与覆盖 | 阶段判断与推进安排 | 王经理将注册考核核查转小林，小林表示不能确认，最终规则责任仍待核（MSG-01824、01907）；门店注册考核完整口径及其与活动的关系未知 |

小林明确表达的是岗位偏好与个人负担，不是公司优先级或收益预期：她更希望先支持优惠券活动，想减少的是整理名单和执行记录、找同事核对不一致信息、反复跟进进度；她未量化工时，也不认为这是复购下滑的原因（MSG-03856、03860）。名单与执行方案仍由业务人员确认。
