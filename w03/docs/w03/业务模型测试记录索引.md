## 三、版本对齐（最容易被问倒的一处）

| 成绩 | 跑在哪个版本 | 能否代表 v0.5 |
| --- | --- | --- |
| 82 题全套（71 通过） | W03 第三稿（`body_sha256 63e0452d…`） | **不能** |
| 11 个主题批次 | 第三稿及分阶段隔离提示 | **不能** |
| 修复 22 题（21 通过） | 隔离回答提示 | **不能** |
| 判据专项（82 判据） | 静态审校，未运行模型 | 不适用 |
| 收尾 7 题（结构 7/7、语义 6/7） | **v0.5** | 只有这一批是 v0.5 |

收尾记录原文写明：**「本批不代表当前版本 82 题全部通过，也不证明通用问答长期稳定；未在本版本重跑的原题为 77 道。原 3/6 和更早 71/82 等成绩保留，不跨版本合并。」**

所以准确表述只有两种：

- 说过程：85 题设计、82 题执行、71 通过、11 批主题回归、v0.5 复验 7 题 6/7。
- 说版本：v0.5 只验了 7 题。

不能说：「业务模型 82 题通过」「v0.5 已验证 85 题」。

## 七、这份索引自身的局限

1. 数字全部来自各目录的自报文件，未逐条重跑复核；各目录内已有 `*_sha256` 与独立评审文件，可追溯性在那边。

4. v0.5 与 82 题版本的正文差异见 `model_changes.md` 与 `artifacts/w03/model-closeout-20261108/`，本索引不做正文级比对。
