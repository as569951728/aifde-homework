# CR-01依据订正：相对时间与覆盖边界

更新：2026-11-18。原单和王经理04838/04840意见完整保留于[原单附件](../../artifacts/w03/revision-20261118/history/变更单-B7-C01.md)及官方访谈JSON，不改写客户原话。本次是交付方纠正提问前提与证据摘要，不是客户已批准撤回或变更。

## 原前提的问题

旧单把“本月”统一当成缺具体月份，期望clarify，并称实际unsupported是产品缺陷。但产品契约已说明相对时间按数据参考日解释：参考日2026-09-01，所以本月可确定为[2026-09-01,2026-10-01)；数据仅覆盖[2024-09-01,2026-09-01)，该月完全在覆盖外。于是unsupported应说明越界，不能凭旧期望将其判错。

## 订正后的区分

| 情况 | 处理 |
| --- | --- |
| 本月可按参考日定位且在覆盖外 | unsupported，说明覆盖边界，不伪报数值 |
| 最近怎么样等缺指标/时间/判断目标 | clarify，先问需要哪项及哪个窗口 |
| 时间明确但指标只支持整月而请求半月 | unsupported，不偷偷替换日期 |

此区分来自既有契约，不需要为B7-C01改意图层；本轮不修改w03_intent_prompt.txt。王经理“含糊问题先问清”的核查原则仍保留。旧单中“本月、上月一律改clarify”的技术方案不再作为我方建议，待用更新证据向其说明，再由客户按原流程处置已提出的单据。

本次另修的是成功回答的半开日期解释，追加一段通用表达约束并全量回归，位置与证据见metric_decisions.md；它不是对业务口径或月份默认规则的修改。
