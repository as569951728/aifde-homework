## 首项：净销售额 net_sales_cents（2026-11-08）

范围：本周青禾合成测试库；本轮只开发这1项，未代表其余37项已完成。以下为导师依据既有材料做的字段映射及核定，不登记本人独立作答或客户新增确认。

| 核定项 | 内容与依据 |
| --- | --- |
| 业务定义 | `01_订单日报说明.md`“净销售额”：paid订单实付减退款后合计；取消单不计；按原订单下单日期归属；单位分 |
| 统计对象与粒度 | 字典orders一行一笔订单，`order_id`唯一；先逐单算贡献，再按窗口/分组求和。不得连接多张卡后重复累计订单 |
| 字段映射 | `status`判纳入；`paid_cents`减`refund_cents`；`ordered_at`确定统计日期。定义对应SUM(CASE WHEN status='paid' THEN paid_cents-refund_cents ELSE 0 END)；这行是导师根据材料的映射，不是假引文 |
| 日期、单位 | Asia/Shanghai本地日期，查询窗口左闭右开；金额保持整数分，解释展示元时再除100；退款是截至快照的累计额，不另按退款发生日拆账 |
| 范围区别 | 本项为通用净销售额，不附加月末付费资格，不套用六项付费月报的整月/全渠道限制；`monthly_paid_sales_cents`为另一项目标 |
| 门店与其他维度 | 成交门店用订单的`store_id`；会员归属门店沿订单账户→members.home_store_id。不得混用两种角色。完整12维度的结构支持与已实际测试的维度分开登记 |
| 零与未知 | 覆盖内空窗的单行加总可为0；缺期间须澄清、覆盖外不支持；不是把未知和错误返回0 |
| 当前依据缺口 | 本指标定义/字段无阻断缺口；本期合成样本不能证明生产数据质量和业务效果 |

来源：[订单日报](../../materials/w03/01_订单日报说明.md)、[财务邮件](../../materials/w03/02_财务邮件.md)、[字典](../../materials/w03/05_数据字典.md)、[业务模型v0.5](business_model.md)。沿用11月5日初核，不重复访谈。

## 构建方法版本切换（2026-11-09）

正式构建方法由 **v0.1.2 切换为 v0.1.5**。v0.1.2 归档在 `customer/w03/build-metrics/archive/SKILL-v0.1.2.md`，未删除。

### 为什么必须切

v0.1.2 只覆盖 B1—B4 那批金额、订单数、账户与比率，缺少三块后续实际用到的规则：

| 新增内容 | 没有它会怎样 | 影响的批次 |
| --- | --- | --- |
| 同一事实的互斥子集与已知零 | 窗口内某账户有有效订单但无首笔订单时，子集缺行会输出 NULL，而不是已知 0 | B5 观测期首购、后续购买 |
| 月末资格型指标 | 无法表达“判定日为自然月末、起日含、计划结束日不含、提前终止当日起无效、多卡任一有效”这套派生规则 | B7 六项付费月报 |
| 引用取原文连续短片段 | 引用会拼接渲染后的标题与正文，跨加粗/链接标记时对不上原文 | B5/B6 定义来源 |

当前 `artifacts/w03/library` 就是 v0.1.5 生成的；若正式方法仍挂 v0.1.2，交付里会出现“库里有月末资格 SQL、方法里没有这条规则”的断点，证据链不成立。

### 切换前已有的证据

- 38 项在 small 上全部通过数值核对；47 题＋8 题的数值 55/55。
- 交付测试集 52 例覆盖 38/38，判定自检 10/10 被拒。
- 规模数据 15 例覆盖 38 项，数值 13/13、拒绝 2/2，版本回填后复判 15/15。

### 边界

这是**方法版本的采用决定**，不是客户验收。v0.1.5 的文字是否与青禾后续书面确认的口径一致，仍按变更流程处理；若业务侧提出不同判定，先改方法、再重建库、再回归，不直接改库。
